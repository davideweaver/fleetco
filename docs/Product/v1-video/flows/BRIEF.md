You are building part of a guide that shows OTC Fleet Services what version 1 of their new shop
software will do. Readers: Dan (business owner) and Kim. Not engineers. They will browse an index
page (`docs/Product/v1-index/index.template.html`, see the `AREAS` array) where every "flow" card
opens either a short narrated **video** or a single **picture**. You build the media for your
assigned cards.

## Narration (female voice, already the default)
- One JSON file per video: `flows/<area>/<key>.json`, array of `{ "id", "text" }`, one entry per scene.
  Scene ids must be unique across your page; prefix them with the key, e.g. `"1.1-title"`.
- First scene is a title card: `cardScreen("Version 1 · <Section name>", "<Flow title>")`, about one
  sentence of narration saying what this clip shows.
- Then 2–5 scenes. Short, plain sentences. Say who is doing what ("The owner…", "The technician…",
  "The customer…"). Use "they" for the technician. No jargon, no em dashes.
- Target the length on the index card (30–60 s). A scene lasts as long as its narration or its
  actions, whichever is longer, so keep each scene's actions within its narration time.

## Pictures
- Define `PICTURES` entries in the same page. Each one sets state and calls `render()` to leave one
  finished, realistic screen (no cursor; it is hidden for pictures). Use `setWho` so the corner tag
  says who uses the screen. A picture can add 1–3 numbered `.note`-style handwritten callouts if that
  helps (see `.note` in `docs/Product/v1-walkthrough-sample.html`), but keep it uncluttered.

## Build commands (run from `docs/Product/v1-video/`)
Model files are at `$M=/tmp/claude-0/-home-user-fleetco/e9c13c34-5416-5555-9035-fe01c64743f5/scratchpad/tts`.
Use your own scratch audio dir. Recording and TTS are CPU-heavy and shared, so ALWAYS wrap them in
the locks exactly as below (they queue behind other agents; that is expected).

```sh
L=/tmp/claude-0/-home-user-fleetco/e9c13c34-5416-5555-9035-fe01c64743f5/scratchpad
# pictures (fast, no lock needed)
node shoot.mjs flows/<area>/<area>.html ../v1-index/media <pictureId> ...
# narration audio for one video
flock $L/tts.lock python3 -I make_audio.py $L/tts flows/<area>/<key>.json $L/audio-<key>
# record one video
flock $L/rec.lock node record.mjs $L/audio-<key> ../v1-index/media/<key>.mp4 flows/<area>/<key>.json flows/<area>/<area>.html
```
`record.mjs` only plays the scenes listed in the narration file, so one page can hold several videos.
Run commands with a long timeout (up to 600000 ms); queueing can take several minutes.

Name media by card key: `1.1.mp4`, `1.2.png`, etc. Picture ids should be the key too (`"1.2"`).

## Check your work
- Before recording, run `shoot.mjs` on a couple of temporary picture ids that show each video screen
  and Read the PNGs: look for overlap, clipping, text running off cards, empty areas.
- After recording, look at the `start/narration/scene` log: if a scene's actions run far past its
  narration, shorten the actions. Extract 3–4 frames with ffmpeg and Read them.
- Fix what you find once, re-record once. Don't loop.
