The Shop Floor

The five areas where we have essentially nothing built, and where FullBay's $5k/month actually goes. This is the session that decides whether the project is "own the portal" or "build a shop system." Everything else can wait.

How to run this

  • Press Start when the recording starts. Every timestamp you capture is an offset from that moment, so marks line up with the transcript. If the recording was already running, put the head-start in seconds into Offset.
  • Ask before you reveal. Each area opens with a question to ask cold. The "what we believe" panel stays closed until after they have answered in their own words — opening it early turns the interview into a confirmation exercise.
  • Hit Mark liberally. One click stamps the current time against that area. Use it whenever something lands; it is how I find the moment in the transcript later.
  • Get the service writer in the room. A manager describes the workflow as designed; the service writer describes what actually happens.
  • Everything saves to this browser as you go. Export at the end and send me the file.

Must ask before the call ends

"If we moved one customer off FullBay, what can you get out of FullBay — any export, report, CSV, anything?"

The API only returns invoices, so a vendor-side export is the only path for history. If the answer is "nothing," history either gets re-keyed by hand or abandoned, and that is a scoping decision they need to make consciously.

"Could a customer move over in one go, with no going back — or do you need both systems running in parallel for a while?"

Parallel running is not available. FullBay has no write API, and the one write path creates a brand-new customer rather than matching the existing one. A hard per-customer cutover is the only shape on offer, and they should hear that now rather than mid-migration.
